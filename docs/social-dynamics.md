# 履歴・交流時間・自律交流モデル

## 比較するモデル

| モード | 信頼・交流履歴 | 交流時間の制約 | 自律的な交流 |
| --- | --- | --- | --- |
| legacy | 更新に使用しない | なし | なし |
| history | あり | なし | なし |
| budget | あり | あり | なし |
| adaptive | あり | あり | あり |

TouchDesignerの初期モードはadaptive。設定→Social Dynamicsで変更し「同じ初期値」で適用する。
PythonのSimulationの初期値はlegacyで、既存実験を維持する。新モデルは `settings=MODES['adaptive']` として明示する。
コミュニティ検出は引き続き関係Aだけを使うCPM＋Leidenであり、所属ラベルは社会更新に使用しない。

## 追加した状態と独自の式

好感度X・相互関係Aとは別に、方向付き信頼T∈[0,1]、実行後の直接交流経験数M、残り時間Bを持つ。
Tの対角は0。既存関係の初期信頼はseed付き乱数で0.2〜0.8、非関係者は0とする。
これは仮の過去履歴で、実際の交流イベントを作ったものではない。Mの初期値は全員0。

- 攻撃の直接効果：`ΔX[v,u] = -eta_v * effective_strength * (1 - protection*T[v,u])`。
- 協力の直接効果は旧モデルの正の更新を維持する。
- 直接の協力による信頼更新：`ΔT[v,u] = learning*effective_strength*(1-T[v,u])`。
- 直接の攻撃による信頼更新：`ΔT[v,u] = -learning*effective_strength`。
- 信頼の経時減衰：`ΔT = -trust_decay*T*(1-0.8*T)`。強い信頼ほど相対的に減衰しにくい。
- 信頼使用時の伝聞の信用度は `T[receiver, source]`。噂ではさらに `1-conflict_discount*max(-X[source,subject],0)` を掛ける。直接目撃の信用度は1。
- 同一バッチの更新は旧状態から合算し、XとTを一度ずつクリップする。

これらの式と数値は先行研究の式の再現ではなく、今回の試作品の仮定。信頼が高くても、攻撃を繰り返して信頼・好感度が低下すれば関係は切れる。

## 有限時間と予約

時間制約モードでは、ボタン操作は次の時刻への予約になる。各人物の時間をsocial_budget（初期値1）に戻し、予約行動を先に処理する。
全員への行動の強さは `min(指定強さ, 残り時間/相手人数)`。各人への最大強さは1。
協力・攻撃では対象人数、噂では直接受信者人数で時間を分ける。全員に実行する仕様は維持するが、人数が多いほど一人当たりの効果は薄まる。
同じ時刻に何度もボタンを押しても予算を超えて実行しない。実行できなかった要求はログに残す。
baselineには予約を入れないため、介入で使った時間により自発的交流が減る差も介入効果の一部に含まれる。

## 自律交流の一時刻

1. 次の時刻へ進め、時間をリセットし、予約した介入を実行する。
2. その後のX・A・Tを固定して情報の伝播と全員の交流希望を計算する。
3. 各人物は相手を一人選ぶ。探索時（確率0.18）は一様ランダム。それ以外は `2X+1.5T+0.5A` を選好スコアとしたsoftmax選択（Gumbel-max実装）。
4. 相手の受諾確率は `sigmoid(2*X[target,actor]+T[target,actor])`。
5. seed・時刻・人物から決まる共通の優先順位で時間を割り当てる。双方に1単位残っていれば交流できる。時間不足は拒絶とは区別し、評価を下げない。
6. 受諾時は双方の時間を1消費し、両方向に `social_gain*(1-X)` と `learning*(1-T)` を加える。関係成立を試みる接触機会にもなる。
7. 拒絶時は誘った側だけ時間0.25を消費し、その側から相手への評価に `-rejection_loss*0.25*(1+X)` を加える。
8. 既存関係の好感度に `-maintenance_decay*X*A` を加える。交流による正の効果と合算する。
9. 情報・自律交流・減衰の要求変化を合算してX/Tを更新し、通常の接触機会も含めて関係・コミュニティを更新する。

提案と受諾の抽選にはPythonのhashや乱数消費順を使わず、従来の安定ハッシュに用途キー11〜15を追加する。
人物ID順の取り合いを避けるため、時間の割当順序にも共有した外生乱数を用いる。実際の相手や接触結果は世界の状態に依存する。
各人物の当該時刻の総消費時間がsocial_budget以下であることをテストしている。

## 観測と停止

「詳細：交流」は信頼、実際の直接交流経験、残り時間、招待・受諾・拒絶・時間不足を表示する。
「詳細：噂」は発信者、対象、到達人数、本人の認知、受信者ごとの信用度・要求評価変化・現在の評価を表示する。
要求変化はその情報によるクリップ前の寄与で、現在の評価には他の交流の影響も含まれる。
噂の真偽、嘘の検出、発信者の悪意の確定、複数証言による信念形成は実装していない。

自律交流または信頼減衰が続く場合は、見かけの安定をabsorbedと判定しない。信頼の変化も安定確認に含める。
画面は従来どおり自動停止せず、利用者が停止する。ヘッドレス実験の終了は指定した観測時刻であり、収束を保証しない。

## 実施した確認と記録

- [単発介入36条件の実測結果](experiments/social_dynamics/results.md)：3シード×4モデル×3行動。全条件と、変化がなかった条件を含む。
- [TouchDesigner実操作の記録](experiments/social_dynamics/ui_checks.json)：MCPから実際のPanelCOMP仮想マウス操作を行い、12条件、開始・一時停止、ステップ、左右の人物選択、JSON/CSV保存を確認。
- `test_social_dynamics.py`：強い信頼による緩和と反復攻撃による切断、時間配分、過剰実行防止、信用と情報到達の区別、再現性、吸収状態の誤判定防止。
- 既存のUIでは右クリック時のUV更新が無効だったため、グラフと親パネルで有効化した。修正後、右クリック選択を実機確認した。

単発の介入では関係が大きく変わらないケースが多い。採用パラメータでの結果であり、派閥化や大規模再編を実証したものではない。
繰り返し行動や係数比較は別の実験条件として追加できる。結果を見て都合のよい試行だけを報告しない。

## 再実行

対応するNumPy・igraph・leidenalgを利用できるPythonから：

```sh
python experiments/run_social_dynamics.py --seeds 23,30,42 --warmup 20 --steps 80 --output results/v3
```

初期X/A/T/人物属性は同一seedで共通。全条件で介入直前までbaselineとinterventionの完全一致を検査し、最後の条件は同じ設定で再実行して最終状態・指標の完全一致を確認する。
モード間では準備期間中の規則が異なるため、介入直前のネットワークは必ずしも同じではない。純粋な機構比較にはwarmup=0も別条件として使用する。
保存するソースハッシュはモデルの同一性の確認に利用する。OS・依存ライブラリ間のビット単位の一致を保証するものではない。
